## PRM-1: Initializer can be called again by anyone

- Location: `src/RewardsPool.sol` lines 14-18
- Found by: slither `pramaan-unprotected-initializer`, aderyn `unprotected-initializer`
- Template: initializer-takeover@1 (slots filled by heuristics)
- Hypothesis: RewardsPool.initialize(address,uint256) can be called again after deployment and hands its caller privileged roles.
- Property: Only the deployer-chosen owner may control the contract after initialization.
- Result: **REPRODUCED: the exploit test passed on this code**
- Gates: ✓ slot-vocabulary, ✓ no-state-forging, ✓ attacker-only, ✓ concrete-assertion

Execution log:

```
pramaan.attacker_gain: 10000000000000000000
```
- Same exploit against `RewardsPoolFixed`: **fails as expected** (already initialized)

### Proposed fix (verified)

RewardsPool.initialize() could be called again to take ownership. It now refuses to run once an owner exists.

```diff
===================================================================
--- a/src/RewardsPool.sol
+++ b/src/RewardsPool.sol
@@ -12,6 +12,7 @@
     event Funded(address indexed from, uint256 amount);
 
     function initialize(address owner_, uint256 rewardRate_) external {
+        require(this.owner() == address(0), "already initialized");
         owner = owner_;
         rewardRate = rewardRate_;
         emit Initialized(owner_, rewardRate_);
```

Re-verification: exploit blocked (reverted: already initialized); 2 regression tests pass
