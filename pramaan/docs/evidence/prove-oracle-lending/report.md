## PRM-5: Oracle answer used without checking that it is positive

- Location: `src/OracleLoan.sol` lines 33-41
- Found by: slither `pramaan-unchecked-oracle`
- Template: oracle-unchecked-price@1 (slots filled by heuristics)
- Hypothesis: OracleLoan.borrow(uint256) uses the price feed's answer without checking that it is positive, so a non-positive answer (cast to uint256) becomes an enormous price.
- Property: A feed that returns a non-positive answer must not let an account holding 1 wei of collateral take ETH that other users deposited.
- Result: **REPRODUCED: the exploit test passed on this code**
- Gates: ✓ slot-vocabulary, ✓ no-state-forging, ✓ attacker-only, ✓ concrete-assertion

Execution log:

```
pramaan.attacker_gain: 10000000000000000000
```
- Same exploit against `OracleLoanFixed`: **fails as expected** (invalid oracle answer)

### Proposed fix (verified)

OracleLoan.borrow() reads the price feed and uses the answer as an unsigned price without checking it. A non-positive answer (an invalid round) is cast to an enormous uint256, which makes any account look massively over-collateralised. The patch rejects non-positive answers.

```diff
===================================================================
--- a/src/OracleLoan.sol
+++ b/src/OracleLoan.sol
@@ -53,6 +53,7 @@
 
     function _price() internal view returns (uint256) {
         (, int256 answer,,,) = feed.latestRoundData();
+        require(answer > 0, "Pramaan: oracle answer is not positive");
         return uint256(answer);
     }
 }
```

Re-verification: exploit blocked (assertion-failed: Pramaan: oracle answer is not positive); 3 regression tests pass
